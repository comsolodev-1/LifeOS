# DECISIONS

- Next.js 16: middleware is named proxy.ts. next-auth v5 beta supports it (peer range includes 16).
- Tailwind 3.4 instead of v4 to keep config simple and stable.
- No shadcn/ui: its generator needs network access that was unavailable; plain Tailwind components in src/components/ui.tsx. Add shadcn later if wanted.
- Auth.js JWT sessions, no adapter: single owner, so no users/accounts/sessions tables. The owner profile row is created on first login.
- Owner allowlist is enforced in the signIn callback and again in requireOwnerEmail on every page and server action.
- All task queries go through src/lib/dal/tasks.ts and require ownerId. Do not query tasks elsewhere.
- Deadlines entered as dates are interpreted as end of day in Asia/Manila (UTC+8, no DST) and stored as UTC. Per-user timezone comes with the Life Profile sprint.
- Mobile nav has 4 tabs plus a More page rather than a bottom sheet.
- System fonts instead of next/font/google, so builds need no network.
- Placeholder pages for later sprints say "Not built yet" instead of showing fake data.
- Deleting a project keeps its tasks (project_id set null). Deleting a task removes its dependency links.
- Dependencies are advisory: a blocked task shows a badge but can still be marked done.
- Cycle checks load the owner's edges and walk them in code (neon-http has no interactive transactions). Fine for one user.
- The DAL is tested against PGlite (real Postgres in memory) through a test-only db seam in src/db/index.ts.
- Expected failures throw AppError and are never retried by withRetry.
- Chat messages, titles, life context, memories and pending payloads are encrypted with VAULT_KEY. Memory search therefore decrypts the owner's approved memories and scores them in code (fine at single-owner scale).
- Assistant messages are stored with real values; every request re-sanitizes them, so tokens stay stable and no placeholders are stored.
- Tool calls and results exist only inside one turn; only the final text is persisted. Gemini 3 thought signatures are replayed within the turn.
- Confirming is exactly-once through a conditional status update (pending to confirming) rather than a transaction, because neon-http has none. A failed write returns the suggestion to pending.
- Memory proposals live in the memories table (status proposed), not pending_actions.
- /api/chat does its own auth and returns 401 JSON instead of redirecting, so the chat UI can show a message.
- Events store UTC plus the IANA zone they were created in. Recurring series expand at read time (never stored as rows) and keep local wall-clock time. Monthly repeats skip months that lack the day (the 31st).
- No all-day or overnight events yet: end time must be later than start time on the same day.
- Weeks start on Monday. Free time is shown for 7 AM to 9 PM only.
- Photos: processed in memory, never persisted. Stripping happens on the phone (canvas re-encode) and again on the server (JPEG, PNG, WebP segment/chunk filtering). The claimed MIME type is ignored; the real type comes from the file bytes.
- The privacy detectors cannot read pixels, so the gateway sends images only with explicit per-upload consent and a cover-box tool; the audit log records only "[image type, size]".
- Photo-derived events are saved as fixed commitments with source "photo", only after the owner reviews them. The server re-validates every row and, for weekly classes, starts the series on the next matching weekday.
- The name-guessing heuristic can tokenize place names such as "Camarines Norte" as people in Strict mode. Accepted trade-off; add exceptions later if it becomes annoying.
- Extraction runs at temperature 0. Gemini can still vary slightly, so the review screen offers a manual re-scan that only adds events not already listed.
- Photo rows that show calendar dates are saved as one-off events by default; the owner can tick "Repeat every week" per row.
